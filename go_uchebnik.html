Go — язык, на котором написаны Docker, Kubernetes и половина серверов в интернете. При этом он специально сделан простым: в нём мало правил, их легко удержать в голове, а программы получаются быстрыми. Отличный первый язык.

Как учиться по этому учебнику

Главное правило: не читай — печатай. Каждый пример набирай руками (не копируй!), запускай, а потом ломай: поменяй число, убери строчку, посмотри, что скажет компилятор. Программирование — это навык рук, а не памяти.

В конце каждой главы есть задачи. Решай их до того, как открыть ответ, даже если получается криво. Криво работающая программа, которую написал сам, учит в десять раз лучше, чем красивая чужая.

Две главы помечены как интерлюдии — они не про Go, а про то, как вообще устроены компьютер и программа. Код в них тоже есть, но если сейчас хочется поскорее писать, их можно пропустить и вернуться позже.

Галочка «прошёл» под каждой главой сохраняется прямо в браузере — прогресс не потеряется.

Установка и первый запуск

Ставим Go, пишем первую программу и учимся читать ругань компилятора.

0.1 Что вообще происходит, когда работает программа

Компьютер умеет очень мало: складывать числа, сравнивать их, класть в память, доставать из памяти. Всё остальное — игры, браузеры, ютуб — собрано из этих кирпичиков, просто их миллиарды в секунду.

Программа — это список команд, записанный так, чтобы компьютер понял. Но напрямую на языке процессора люди не пишут: это адски неудобно. Поэтому пишут на языке программирования — почти человеческом тексте, — а специальная программа переводит его в машинные команды.

У Go этот переводчик называется компилятор. Он берёт твой текстовый файл и делает из него готовое приложение — один файл, который можно запустить или отдать другу.

Компилятор против интерпретатора

Переводить код в машинные команды можно двумя способами.

Интерпретатор читает программу по кусочку прямо во время работы — как синхронный переводчик. Удобно, но медленнее, и ошибку в строке 300 ты увидишь, только когда выполнение до неё дойдёт.

Компилятор переводит всю программу заранее, целиком. Поэтому она работает быстро, а большинство опечаток и глупостей ловится до запуска. Для новичка это огромный плюс: язык ругается сразу, а не через полчаса работы.

Go идёт вторым путём — и дальше в учебнике мы будем считать именно так.

Тонкость, о которой стоит знать сразу

Часто говорят «Go — компилируемый язык, а Python — интерпретируемый». Это удобное сокращение, но не совсем правда: компилируемых и интерпретируемых языков не бывает — бывают компиляторы и интерпретаторы конкретного языка. Описание Go говорит, что программа означает, а не каким способом её исполнять.

Поэтому интерпретаторы Go существуют — например yaegi и gomacro: они исполняют Go-исходники на лету и дают REPL, где можно набирать код построчно, как в Python. Их используют для плагинов, чтобы не пересобирать программу целиком. И наоборот: для Python есть компилятор в машинный код (Nuitka), а для C — интерпретатор (Cling).

Так что «Go компилируемый» — утверждение не про язык, а про то, как его готовят на практике: штатный путь ровно один, и почти все ходят именно им.

0.2 Почему именно Go

  • Маленький. В Go всего 25 ключевых слов. В C++ — больше сотни. Весь язык реально выучить за пару недель.
  • Строгий, но добрый. Компилятор не пустит тебя дальше, пока не исправишь ошибку. Сначала бесит, потом понимаешь, что он спас тебя от часа отладки.
  • Один файл на выходе. Скомпилировал — получил приложение. Не нужно ставить Go тому, кому ты его отправил.
  • Быстрый. По скорости близок к C, а писать почти так же легко, как на Python.
  • Востребованный. Docker, Kubernetes, Telegram-боты, серверы Twitch и Uber — это Go.

0.4 Редактор

Писать код можно хоть в Блокноте, но это мазохизм. Поставь VS Code (code.visualstudio.com), открой вкладку расширений (Ctrl+Shift+X) и найди расширение Go от Google. Установи. Когда откроешь первый .go-файл, VS Code предложит доустановить инструменты — соглашайся на всё.

Что ты за это получаешь: подсветку синтаксиса, подсказки по функциям, автоформатирование при сохранении и подчёркивание ошибок красным ещё до запуска.

0.5 Первая программа

Создай где-нибудь папку hello. Открой её в VS Code (File → Open Folder). Открой встроенный терминал (Ctrl+`) и набери:

терминал
go mod init hello
go: creating new go.mod: module hello

Эта команда объявляет папку модулем — то есть отдельным проектом. Что это значит подробно — в главе 13, пока просто делай так в начале каждого нового проекта.

Теперь создай файл main.go и набери в нём (руками!):

main.go
package main

import "fmt"

func main() {
    fmt.Println("Привет! Я живой.")
}

Запускай:

терминал
go run .
Привет! Я живой.

Всё. Ты программист. Теперь разберём, что тут написано.

0.6 Разбор по косточкам

СтрокаЧто означает
package main«Этот файл принадлежит пакету main». Пакет — это папка с кодом. Имя main — особенное: оно означает «это запускаемая программа, а не библиотека».
import "fmt"«Подключи готовый пакет fmt». Он умеет печатать текст на экран. Название — от format.
func main()Объявление функции с именем main. Функция — это именованный кусок кода. main тоже особенная: именно с неё начинается выполнение программы.
{ }Фигурные скобки — «тело» функции, то есть то, что она делает. Всё между ними выполнится по очереди сверху вниз.
fmt.Println(...)«Возьми из пакета fmt функцию Println и вызови её». Точка означает «внутри». Println = print line, печатает текст и переводит строку.
"Привет!..."Текст в двойных кавычках — строка. Кавычки не печатаются, они лишь говорят компилятору: «это текст, не команда».
Println и Print

fmt.Println("а") печатает а и переходит на новую строку. fmt.Print("а") — печатает и остаётся на той же строке. Попробуй оба варианта подряд и посмотри на разницу.

0.7 Как читать ошибки

Сотри точку с запятой... то есть закрывающую скобку. Убери последнюю } и запусти. Компилятор скажет что-то вроде:

терминал
./main.go:7:1: syntax error: unexpected EOF, expecting }

Читается так: файл main.go, строка 7, символ 1 — синтаксическая ошибка, неожиданный конец файла, ожидалась }. Всегда смотри на номер строки первым делом и иди туда.

Самая частая ошибка новичка

declared and not used: x — «переменная x объявлена, но не используется». В Go это ошибка, а не предупреждение: программа не соберётся. Логика такая: если переменная не нужна — удали её, иначе она путает читателя. Так же строго с неиспользуемыми импортами.

0.8 Три команды, которые понадобятся всегда

КомандаЧто делает
go run .Скомпилировать и сразу запустить. Основной режим во время учёбы.
go buildСобрать готовое приложение в файл (hello или hello.exe). Его можно отправить другу.
gofmt -w .Причесать отступы и пробелы во всех файлах. В Go есть единственный правильный стиль форматирования, и спорить о нём не принято. VS Code делает это сам при сохранении.

go run . легко принять за интерпретатор: набрал команду — программа побежала, как питоновский скрипт. Но внутри происходит обычная компиляция во временный файл, который тут же запускается и потом выбрасывается. Просто Go делает это так быстро, что разницы не чувствуешь.

Задача 0.1

Сделай так, чтобы программа напечатала три строки: своё имя, свой любимый цвет и текущий год.

Решение
main.go
package main

import "fmt"

func main() {
    fmt.Println("Андрей")
    fmt.Println("синий")
    fmt.Println(2026)
}

Заметь: число пишется без кавычек. Println умеет печатать и текст, и числа.

Задача 0.2

Нарисуй ёлку из символов * высотой пять строк. Пока — просто пятью вызовами Println.

Решение
main.go
fmt.Println("    *")
fmt.Println("   ***")
fmt.Println("  *****")
fmt.Println(" *******")
fmt.Println("   |||")

В главе 4 научимся рисовать такую ёлку любой высоты тремя строчками кода.

Задача 0.3 — сломай специально

Поочерёдно сделай четыре вещи и запиши, что скажет компилятор: (1) убери import "fmt"; (2) напиши Fmt.Println с большой буквы; (3) напиши fmt.println с маленькой; (4) убери закрывающую кавычку у строки.

Что ты увидишь
  • undefined: fmt — забыл импорт.
  • undefined: Fmt — имена пакетов пишутся с маленькой буквы, регистр важен.
  • undefined: fmt.println — а вот имена функций из пакета видны снаружи только если начинаются с большой буквы. Это правило Go, к нему привыкнешь.
  • string not terminated — незакрытая строка.

Смысл задачи: перестать бояться красного текста. Ошибка компилятора — это подсказка, а не ругательство.

Интерлюдия 1. Как устроена программа

Компьютерная наука без формул: из чего сделан компьютер, что лежит внутри готовой программы и что происходит в момент запуска.

Эта глава — не про Go, а про то, что находится под ним. Её можно пролистать и вернуться позже, но если прочитать сейчас, дальше многое перестанет быть магией: почему число занимает 8 байт, откуда берётся «переполнение стека», почему программа из пяти строк весит два мегабайта и куда вообще уходит текст, который ты печатаешь через Println.

И1.1 Компьютер умеет очень мало

Внутри процессора нет ничего умного. Он крутит один и тот же цикл: достать очередную команду из памяти → выполнить → перейти к следующей. И так несколько миллиардов раз в секунду.

Команды примитивные до неприличия: сложить два числа, сравнить два числа, скопировать число из памяти в регистр (сверхбыструю ячейку внутри процессора) и обратно, прыгнуть на другую команду, если предыдущее сравнение дало «да». Всё. Из этого набора собраны браузеры, игры и нейросети — просто кирпичиков очень много.

Оперативная память (ОЗУ) — длиннющий ряд пронумерованных ячеек размером в байт. Номер ячейки называется адресом. Когда в главе 10 появятся указатели, речь пойдёт именно об этих номерах, ничего мистического там нет.

Внутри всё — числа

Бит — одна ячейка, в которой либо 0, либо 1. Восемь бит — байт, в него влезает число от 0 до 255. Больше в памяти нет ничего: ни букв, ни картинок, ни звука — только байты.

Буква получается из договорённости: «байт 65 будем рисовать как A». Цвет пикселя — три байта: сколько красного, зелёного, синего. Звук — тысячи чисел в секунду, каждое означает положение мембраны динамика.

Отсюда простая мысль: тип — это и есть договорённость, как читать байты. Одни и те же четыре байта могут быть целым числом, дробным числом и четырьмя буквами — разница только в том, кем ты их объявил. Поэтому Go так придирчив к типам: сами байты молчат и ничего о себе не сообщают.

Память бывает разной скорости, и это влияет на всё. Порядок величин примерно такой:

Разница между первой и последней строкой — примерно как между «дотянуться рукой» и «съездить в другой город». Именно поэтому программы стараются держать нужные данные поближе, а поход в сеть считают дорогим событием.

И1.2 Программа на диске — это просто файл

Пока ты пишешь main.go, никакой программы ещё нет: есть текст. Программой он становится после сборки.

терминал
go build -o hello .
ls -lh hello
file hello
-rwxr-xr-x 1 anya anya 1.9M hello hello: ELF 64-bit LSB executable, x86-64, statically linked, not stripped

Что лежит внутри этого файла:

  • Машинный код — те самые примитивные команды процессора, в которые компилятор перевёл твои for и if.
  • Данные — всё, что известно заранее: строковые литералы, константы, таблицы.
  • Заголовок — служебная анкета для операционной системы: под какой процессор собрано, с какого места начинать выполнение, сколько памяти запросить. В Linux формат заголовка называется ELF, в Windows — PE (это те самые .exe), в macOS — Mach-O. Поэтому .exe нельзя просто так запустить на Linux: анкета заполнена не по той форме.
  • Отладочная информация — карта соответствия «эта машинная команда получилась вот из этой строки твоего файла». Нужна отладчику и красивым сообщениям об ошибках.
Почему «Привет» весит два мегабайта

В файл попадает не только твой код. Go кладёт туда рантайм — небольшую операционную систему внутри программы: сборщик мусора, планировщик горутин, обработчик паник, работа с сетью и файлами. Плюс отладочные таблицы.

Отладочную часть можно выбросить: go build -ldflags="-s -w" ужимает те же полтора-два мегабайта примерно до 1,2 МБ. Дальше уже почти не сжать — рантайм нужен для работы.

Взамен ты получаешь главное удобство Go: это один самодостаточный файл. Его можно скопировать на чужую машину, где нет ни Go, ни библиотек, и он запустится. Программе на Python нужен установленный Python, программе на Java — виртуальная машина; здесь — ничего.

И1.3 Что происходит, когда ты нажал Enter

Ты набрал ./hello и нажал Enter. Дальше по шагам:

  1. Оболочка (терминал) просит операционную систему запустить этот файл.
  2. ОС читает заголовок, проверяет, что файл ей по зубам, и создаёт процесс: выделяет ему память, загружает туда код и данные.
  3. Процессу выдаются три уже открытых канала связи с миром — ввод, вывод и вывод ошибок. Про них будет вся следующая интерлюдия.
  4. ОС ставит «палец» процессора на точку входа — и начинает выполняться код. В Go сначала стартует рантайм: он готовит память, запускает сборщик мусора и планировщик, а уже потом вызывает твою main.
  5. Когда main заканчивается, процесс завершается, а вся его память возвращается системе.
Программа и процесс — разные вещи

Программа — файл на диске, рецепт. Процесс — запущенный экземпляр, готовка по этому рецепту. Один файл может работать в двадцати процессах одновременно, и у каждого будет своя память и свои переменные: они друг о друге ничего не знают.

Посмотреть на живые процессы можно диспетчером задач или командой ps aux в терминале. Всё, что там перечислено, — такие же программы, как та, что ты собрал минуту назад.

И1.4 Память процесса: код, стек и куча

Память, которую ОС выдала процессу, поделена на области с разным характером:

Стек устроен как стопка тарелок. Вызвали функцию — сверху лёг её «кадр»: аргументы, локальные переменные, адрес, куда вернуться. Функция закончилась — кадр снят, память свободна мгновенно и бесплатно. Именно поэтому локальные переменные такие дешёвые.

И именно поэтому плохо заканчивается программа, в которой функция бесконечно вызывает саму себя: кадры кладутся один на другой, никто их не снимает, и стопка упирается в потолок. Go в этот момент говорит прямым текстом:

runtime: goroutine stack exceeds 1000000000-byte limit fatal error: stack overflow

Кстати, вот и ответ на вопрос, почему горутин можно запускать сотнями тысяч (глава 15): стек горутины стартует с пары килобайт и растёт по мере надобности, а не занимает мегабайты заранее, как поток операционной системы.

Куча — для всего, что должно жить дольше одного вызова. Куда положить конкретное значение, решает не программист, а компилятор: он смотрит, остаётся ли значение внутри функции или его адрес «убегает» наружу. Если убегает — значение переезжает в кучу, потому что стек к моменту возврата уже свернётся. Это называется escape-анализ, и увидеть его решения можно командой go build -gcflags=-m . — в её выводе попадаются строчки вида moved to heap. Знать это наизусть не нужно; пока достаточно понимать, что в главе 10 речь пойдёт ровно об этих «убегающих адресах».

Кто убирает мусор

В C программист сам говорит «эта память больше не нужна» — и если забудет, память утекает, а если освободит дважды, программа падает. Из этих двух ошибок выросла добрая половина уязвимостей в истории.

В Go работает сборщик мусора: он периодически смотрит, до каких данных в куче ещё можно дотянуться из живого кода, а остальное забирает. Ты просто перестаёшь пользоваться значением, и оно исчезает само.

Цена — маленькие паузы и немного лишней памяти. Для абсолютного большинства программ это отличная сделка, поэтому так же устроены Java, C#, Python и JavaScript.

И1.5 Операционная система и системные вызовы

Важная вещь, которая обычно доходит не сразу: твоя программа не имеет прямого доступа к железу. Она не пишет в экран, не читает диск и не отправляет пакеты в сеть. Всё это она просит сделать операционную систему.

Такая просьба называется системным вызовом (syscall). Печать строки на экран — это системный вызов write. Его можно увидеть своими глазами (на Linux):

терминал
strace -e trace=write ./hello
write(1, "\320\237\321\200\320\270\320\262\320\265\321\202!\n", 14) = 14 +++ exited with 0 +++

Вот и весь fmt.Println("Привет!"): одна просьба к ядру — «запиши 14 байт в канал номер 1». Что за канал номер 1, разберём в следующей интерлюдии.

Зачем такая бюрократия? Во-первых, безопасность: иначе любая программа могла бы прочитать чужие файлы и залезть в память соседа. Во-вторых, дележ: процессор, диск и сеть одни, а желающих много, и кто-то должен выдавать очередь.

И1.7 Немного про алгоритмы: за всё платят временем

Вторая половина компьютерной науки — не «как устроено», а «сколько стоит». Один и тот же результат можно получить способами, которые различаются в тысячи раз.

Простейший пример: найти число среди миллиона других. В списке приходится проверять элементы подряд, один за другим, — в среднем это полмиллиона сравнений. В карте (глава 7) из ключа один раз вычисляется номер ячейки, и программа сразу приходит по адресу, сколько бы данных ни лежало рядом. На миллионе элементов первый способ занимает около миллисекунды, второй — меньше микросекунды.

Разница не в полтора раза, а примерно в полторы тысячи. И чем больше данных, тем сильнее разрыв: список замедляется вместе с ростом, а карта — почти нет. Замерить это своими руками ты сможешь в главе 7, когда появятся и срезы, и карты.

Чтобы говорить об этом коротко, придумали запись O-большое. Она отвечает на один вопрос: что будет со временем работы, если данных станет в десять раз больше?

O(log n)ЛогарифмическоеЧуть-чуть дольшеПоиск в отсортированном списке пополам

Главная ловушка новичка — вложенные циклы

Цикл внутри цикла по одним и тем же данным — это O(n²). На тесте из 10 элементов всё летает, на реальных 100 000 программа встаёт намертво: сто тысяч в квадрате — это десять миллиардов проверок.

Лекарство почти всегда одно: сложить данные в карту и заменить внутренний цикл поиском по ключу. Так квадрат превращается в линию.

Но не увлекайся заранее. Известное правило: сначала пиши понятно, потом измеряй, и только потом ускоряй то место, которое реально тормозит. Чаще всего оно оказывается не там, где ты думал.

Переменные и типы

Как программа запоминает вещи и почему Go так придирчив к тому, что именно ты запоминаешь.

1.1 Переменная — это подписанная коробка

Программе нужно где-то хранить данные: счёт в игре, имя игрока, температуру за окном. Для этого есть переменные — участки памяти, которым ты дал имя.

main.go
package main

import "fmt"

func main() {
    var score int = 10
    var name string = "Аня"

    fmt.Println(name, "набрала", score, "очков")

    score = 25 // положили в ту же коробку другое число
    fmt.Println("Теперь:", score)
}
Аня набрала 10 очков Теперь: 25

Разбор строки var score int = 10:

  • var — «объявляю переменную»;
  • score — её имя (придумываешь ты);
  • int — её тип, то есть какого сорта данные тут лежат (целое число);
  • = 10 — начальное значение.

1.2 Короткая форма :=

Писать var и тип каждый раз лень, и Go это понимает. Внутри функции работает короткое объявление:

main.go
score := 10          // Go сам понял: это int
name := "Аня"        // а это string
pi := 3.14           // это float64
alive := true        // это bool

Именно так пишут в 95% случаев. Полную форму var используют, когда нужно объявить переменную без начального значения или задать тип вручную.

Две разные штуки: := и =

:= — «создай новую переменную и положи туда». Работает только один раз для каждого имени.
= — «положи в уже существующую переменную».

Если написать score := 10 дважды, компилятор скажет no new variables on left side of :=.

1.3 Четыре базовых типа

ТипЧто хранитПримеры
intЦелые числа, положительные и отрицательные0, -7, 1000000
float64Числа с дробной частью3.14, -0.5, 2.0
stringТекст"привет", "", "42"
boolПравда или ложь. Всего два значенияtrue, false

Есть и другие (int8, uint, float32, byte, rune), но новичку хватает этих четырёх. Про rune поговорим в главе 8.

Почему тип нельзя менять

В Go переменная получает тип навсегда. Положить строку в int нельзя — компилятор откажется собирать программу.

Кажется, что это ограничение. На самом деле это защита. В языках, где так можно, легко получить "5" + 3 и потратить час на выяснение, почему получилось "53", а не 8. В Go такая программа просто не запустится, и ты узнаешь о проблеме за секунду.

1.4 Нулевые значения

Если объявить переменную без значения, Go не оставит там мусор — он положит «нулевое значение» типа:

main.go
var a int      // 0
var b float64  // 0
var c string   // "" (пустая строка)
var d bool     // false

fmt.Println(a, b, c, d)
0 0 false

Это удобно: не бывает «неинициализированной» переменной с непредсказуемым содержимым, как в C.

1.5 Арифметика

main.go
a := 17
b := 5

fmt.Println(a + b)  // 22
fmt.Println(a - b)  // 12
fmt.Println(a * b)  // 85
fmt.Println(a / b)  // 3  ← внимание!
fmt.Println(a % b)  // 2  ← остаток от деления
Целые делятся нацело

17 / 5 даёт 3, а не 3.4. Оба числа целые — значит и результат целый, дробная часть отбрасывается. Чтобы получить 3.4, хотя бы одно число должно быть дробным: 17.0 / 5.

Оператор % («остаток», по-английски modulo) очень полезен: n % 2 == 0 — это проверка «число чётное».

1.6 Преобразование типов

Сложить int и float64 напрямую нельзя — Go потребует явно сказать, что ты делаешь:

main.go
count := 7          // int
price := 12.5       // float64

// total := count * price   ← ошибка: mismatched types int and float64
total := float64(count) * price
fmt.Println(total)
87.5

Запись float64(count) означает «сделай из count дробное число». Обратно тоже можно: int(3.99) даст 3 — дробная часть просто отрезается, без округления.

1.7 Константы

Если значение не должно меняться никогда — объявляй константу:

main.go
const maxPlayers = 4
const appName = "Пингвин"

// maxPlayers = 5   ← ошибка: cannot assign to maxPlayers

1.8 Как называть переменные

  • По-английски и по смыслу: userName, а не a1 или imya.
  • Несколько слов — camelCase: первое слово с маленькой, остальные с большой. totalScore, isReady.
  • Для очень коротких кусков кода нормально i, n, x. В Go это не считается плохим тоном, если переменная живёт три строки.
  • Булевы переменные удобно называть с is/has: isDone, hasKey.

Ввод и вывод

Учим программу красиво печатать и разговаривать с пользователем.

2.1 Printf: печать по шаблону

Println печатает всё через пробел и годится для отладки. Но когда нужен контроль над видом — берут Printf (print formatted). Ему дают шаблон с «дырками», а потом значения, которые в эти дырки вставятся.

main.go
name := "Аня"
tasks := 3
score := 26
total := tasks * 10

avg := float64(score) / float64(tasks)
percent := score * 100 / total

fmt.Printf("%s набрала %d очков из %d\n", name, score, total)
fmt.Printf("Средний балл: %.2f\n", avg)
fmt.Printf("Выполнено: %d%%\n", percent)
Аня набрала 26 очков из 30 Средний балл: 8.67 Выполнено: 86%

В строке score * 100 / total прячутся сразу два подвоха из главы 1.5. Порядок: сначала умножаем, потом делим — если написать score / total * 100, получится 0, потому что целое 26 / 30 обнуляется ещё до умножения. И результат целый: точные 86,67% превращаются в 86, остаток отбрасывается.

В конце шаблона почти всегда нужен \n — это «символ новой строки». Забудешь — всё слипнется в одну кашу. Ещё есть \t (табуляция) и \" (кавычка внутри строки).

2.2 Sprintf: собрать строку, а не печатать

Тот же шаблон, но результат не уходит на экран, а возвращается строкой. Она становится обычным значением: её можно положить в переменную, склеить с другой, передать дальше — сделать всё то, чего с напечатанным текстом уже не сделаешь.

main.go
name := "Аня"
level := 7

msg := fmt.Sprintf("Игрок %s, уровень %d", name, level)
file := fmt.Sprintf("save_%s_%d.txt", name, level)

fmt.Println(msg)
fmt.Println("Сохраняю в", file)
Игрок Аня, уровень 7 Сохраняю в save_Аня_7.txt

Первую строку можно было бы напечатать и через Printf — разницы не видно. А вот вторая показывает суть: имя файла нужно не на экране, а как значение, которым потом откроют файл. Печатать его тут — только чтобы ты убедился, что оно собралось правильно.

2.3 Читаем с клавиатуры

Самый простой способ — fmt.Scanln. Он читает одно слово и кладёт его в переменную.

Забегаем вперёд: знак &

Перед именем переменной ниже стоит &. Это адрес переменной, и по-настоящему адреса разбираются в главе 10. До тех пор читай &name как «вот сюда положи»: без адреса Scanln заполнил бы свою собственную копию, а твоя переменная осталась бы пустой. Это единственное место в первых главах, где приходится пользоваться конструкцией раньше, чем она объяснена.

main.go
package main

import "fmt"

func main() {
    var name string

    fmt.Print("Как тебя зовут? ")
    fmt.Scanln(&name)

    fmt.Printf("Привет, %s!\n", name)
}
Как тебя зовут? Аня Привет, Аня!

Числа читаются так же:

main.go
var age int
fmt.Print("Сколько тебе лет? ")
fmt.Scanln(&age)
fmt.Printf("Через 10 лет тебе будет %d\n", age+10)

Знак + склеивает только строки со строками. Как только в склейке появляется число, нужен Sprintf из 2.2: он и подставит значение, и вернёт готовую строку.

До сих пор код шёл сверху вниз без вариантов. Пора научить его выбирать.

3.1 if и else

main.go

Ещё нет

Скобка на той же строке

В Go нельзя переносить { на следующую строку:

{                    // ← ошибка компиляции!

}

Причина техническая: Go автоматически ставит невидимую точку с запятой в конце строки, и после 18 условие «закрывается». Просто всегда пиши { на той же строке — так делают все.

Циклы: повторяем без копипасты

В Go всего одно слово для всех видов циклов — for. И это, честно, удобно.

4.1 Обычный счётный цикл

main.go
for i := 1; i <= 5; i++ {
    fmt.Println("шаг", i)
}
шаг 1 шаг 2 шаг 3 шаг 4 шаг 5

В заголовке три части, разделённые точками с запятой:

  1. i := 1 — подготовка, выполняется один раз перед началом;
  2. i <= 5 — условие, проверяется перед каждым повторением; как только оно ложно — цикл заканчивается;
  3. i++ — шаг, выполняется после каждого повторения. i++ — короткая запись для i = i + 1.

4.2 Цикл-«пока»

Если оставить только условие, получится то, что в других языках называют while:

main.go
n := 100
steps := 0

for n > 1 {
    if n%2 == 0 {
        n = n / 2
    } else {
        n = 3*n + 1
    }
    steps++
}

fmt.Println("дошли до 1 за", steps, "шагов")
дошли до 1 за 25 шагов

Это гипотеза Коллатца: берём число, чётное делим пополам, нечётное умножаем на 3 и прибавляем 1. Считается, что так любое число рано или поздно придёт к единице — но никто до сих пор не смог этого доказать. Попробуй число 27.

4.3 Бесконечный цикл и break

main.go
count := 0

for {
    count++
    if count == 3 {
        fmt.Println("хватит")
        break        // выйти из цикла немедленно
    }
    fmt.Println("кручусь", count)
}
кручусь 1 кручусь 2 хватит

Такой цикл — основа любой интерактивной программы: «крутись вечно, показывай меню, выходи по команде».

Родственник break — continue: он не выходит из цикла, а перескакивает к следующему повторению.

main.go
for i := 1; i <= 10; i++ {
    if i%2 != 0 {
        continue      // нечётные пропускаем
    }
    fmt.Print(i, " ")
}
2 4 6 8 10
Если программа зависла

Забыл увеличить счётчик — цикл крутится вечно и терминал забивается текстом. Нажми Ctrl+C: это универсальная команда «убить программу». Ничего страшного не произошло, просто исправь условие.

4.4 Вложенные циклы

Цикл внутри цикла. Внутренний прокручивается полностью на каждый шаг внешнего.

main.go
for row := 1; row <= 3; row++ {
    for col := 1; col <= 4; col++ {
        fmt.Printf("%d.%d  ", row, col)
    }
    fmt.Println()      // перевод строки после каждого ряда
}
1.1 1.2 1.3 1.4 2.1 2.2 2.3 2.4 3.1 3.2 3.3 3.4

А вот и обещанная ёлка любой высоты:

main.go
height := 6

for i := 1; i <= height; i++ {
    fmt.Print(strings.Repeat(" ", height-i))
    fmt.Print(strings.Repeat("*", 2*i-1))
    fmt.Println()
}
* *** ***** ******* ********* ***********

strings.Repeat(s, n) — повторить строку n раз. Не забудь import "strings".

Проект 1

Угадай число

Первая настоящая программа: компьютер загадывает число, ты угадываешь, он подсказывает «больше/меньше» и считает попытки.

Что закрепляем: ввод с клавиатуры, циклы, условия, случайные числа.

Шаг 1. Случайное число

Пакет math/rand умеет выдавать случайные числа. rand.Intn(100) даёт число от 0 до 99, поэтому прибавим 1.

main.go
package main

import (
    "fmt"
    "math/rand"
)

func main() {
    secret := rand.Intn(100) + 1
    fmt.Println("загадано:", secret)   // временно, для проверки
}

Шаг 2. Цикл угадывания

main.go
package main

import (
    "fmt"
    "math/rand"
)

func main() {
    secret := rand.Intn(100) + 1
    tries := 0

    fmt.Println("Я загадал число от 1 до 100. Угадаешь?")

    for {
        var guess int
        fmt.Print("> ")
        fmt.Scanln(&guess)
        tries++

        if guess < secret {
            fmt.Println("Больше")
        } else if guess > secret {
            fmt.Println("Меньше")
        } else {
            fmt.Printf("Точно! Попыток: %d\n", tries)
            break
        }
    }
}
Я загадал число от 1 до 100. Угадаешь? > 50 Меньше > 25 Больше > 37 Больше > 43 Точно! Попыток: 4
Стратегия, которую стоит понять

Если каждый раз называть середину оставшегося диапазона, любое число от 1 до 100 находится максимум за 7 попыток. Это двоичный поиск — один из самых важных алгоритмов вообще. Каждый вопрос выкидывает половину вариантов: 100 → 50 → 25 → 13 → 7 → 4 → 2 → 1.

Шаг 3. Доработай сам

  • Ограничь число попыток семью. Кончились — «Ты проиграл, было загадано N».
  • Подсказывай теплее: если промах меньше 5 — «Совсем рядом!».
  • После победы спроси «Играем ещё? (д/н)» и начни заново, если ответили «д». Понадобится ещё один цикл снаружи.
  • Поменяй роли: ты загадываешь число, а компьютер угадывает по двоичному поиску, а ты отвечаешь «больше/меньше/угадал». Считай его попытки — их всегда будет 7 или меньше.
Подсказка к варианту «компьютер угадывает»
main.go
low, high := 1, 100
tries := 0

for {
    mid := (low + high) / 2
    tries++
    fmt.Printf("Твоё число %d? (б/м/да) ", mid)

    var answer string
    fmt.Scanln(&answer)

    if answer == "да" {
        fmt.Println("Угадал за", tries)
        break
    } else if answer == "б" {
        low = mid + 1
    } else {
        high = mid - 1
    }
}

Функции

Как перестать копировать код и начать собирать программу из деталей.

5.1 Зачем

Представь, что в программе три места, где нужно посчитать площадь круга. Можно трижды написать 3.14159 * r * r. А потом узнать, что нужно больше знаков в числе пи — и править в трёх местах, забыв про одно.

Функция — это кусок кода, которому дали имя. Написал один раз, вызываешь сколько угодно.

main.go
package main

import "fmt"

func circleArea(r float64) float64 {
    return 3.14159 * r * r
}

func main() {
    fmt.Println(circleArea(1))
    fmt.Println(circleArea(2.5))
}
3.14159 19.6349375

Разбор заголовка func circleArea(r float64) float64:

  • func — объявляю функцию;
  • circleArea — имя;
  • (r float64) — параметр: что функция принимает. Сначала имя, потом тип;
  • второй float64 — тип результата: что функция отдаёт обратно;
  • return — «вот ответ, заканчиваем».

5.2 Несколько параметров, ничего не возвращаем

main.go
// два параметра одного типа можно перечислить через запятую
func rectArea(w, h float64) float64 {
    return w * h
}

// функция без результата — просто делает что-то
func greet(name string) {
    fmt.Printf("Привет, %s!\n", name)
}

func main() {
    fmt.Println(rectArea(3, 4))
    greet("Аня")
}

5.3 Два значения на выходе — фирменный приём Go

В большинстве языков функция возвращает одну вещь. В Go — сколько угодно, и это меняет стиль кода.

main.go
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, fmt.Errorf("деление на ноль")
    }
    return a / b, nil
}

func main() {
    result, err := divide(10, 3)
    if err != nil {
        fmt.Println("ошибка:", err)
        return
    }
    fmt.Printf("%.3f\n", result)

    _, err = divide(1, 0)
    fmt.Println("а тут:", err)
}
3.333 а тут: деление на ноль

Именно так в Go сообщают о проблемах: вторым значением возвращают error. Если всё хорошо — там nil («ничего»). Подробно — в главе 12, но привыкай к шаблону уже сейчас:

Шаблон, который ты напишешь тысячу раз 
value, err := что-тоРискованное()
if err != nil {
    // разбираемся с проблемой
    return
}
// работаем с value

5.4 Область видимости

Переменная живёт внутри тех фигурных скобок, где объявлена. Снаружи её не существует.

main.go
func main() {
    x := 10

    if x > 5 {
        y := 20
        fmt.Println(x, y)   // здесь видны обе
    }

    // fmt.Println(y)       ← ошибка: undefined: y
}

Функции не видят переменные друг друга — это и есть их сила. Функция общается с миром только через параметры и результат, поэтому её можно понять, не читая остальную программу.

5.5 Функция вызывает саму себя

Это называется рекурсия. Звучит странно, но иногда это самый понятный способ.

main.go
func factorial(n int) int {
    if n <= 1 {
        return 1          // база: дальше не спускаемся
    }
    return n * factorial(n-1)
}

func main() {
    fmt.Println(factorial(5))   // 5*4*3*2*1
}
120
Без базы — бесконечность

Если убрать проверку if n <= 1, функция будет вызывать себя вечно и программа упадёт с stack overflow. У любой рекурсии обязательно должен быть случай, когда она останавливается.

5.6 Функция как значение

Функцию в Go можно положить в переменную и передать другой функции. Пока просто посмотри, дальше пригодится:

main.go
func applyTwice(f func(int) int, x int) int {
    return f(f(x))
}

func main() {
    double := func(n int) int { return n * 2 }

    fmt.Println(applyTwice(double, 3))   // 3 → 6 → 12
}
12

5.7 defer — «сделай это в конце»

Строка с defer выполнится не сейчас, а когда функция будет заканчиваться — что бы ни случилось.

main.go
func main() {
    defer fmt.Println("третий")
    fmt.Println("первый")
    fmt.Println("второй")
}
первый второй третий

Зачем? Чтобы не забыть прибраться. Открыл файл — сразу пиши defer file.Close(), и файл закроется, даже если посреди функции случится ошибка и ты выйдешь через return. Увидим это в главе 14.

Списки: массивы и срезы

Одна переменная — одно значение. А если нужно хранить сто оценок или всех игроков?

6.1 Массив: коробка фиксированного размера

main.go
var scores [5]int          // пять нулей
scores[0] = 10
scores[4] = 42

fmt.Println(scores)
fmt.Println("длина:", len(scores))
[10 0 0 0 42] длина: 5

Элементы нумеруются с нуля: у массива на 5 элементов индексы 0, 1, 2, 3, 4. Обращение к scores[5] — выход за границы, программа упадёт с index out of range.

Размер массива — часть его типа и менять его нельзя. Поэтому в реальном коде массивы используют редко. Гораздо чаще — срезы.

6.2 Срез (slice): список, который растёт

main.go
names := []string{"Аня", "Боря", "Витя"}   // квадратные скобки пустые!

fmt.Println(names)
fmt.Println(names[1])
fmt.Println(len(names))

names = append(names, "Галя")               // добавили в конец
fmt.Println(names, len(names))
[Аня Боря Витя] Боря 3 [Аня Боря Витя Галя] 4
append нужно присваивать обратно

append(names, "Галя") сам по себе ничего не меняет — он возвращает новый срез. Правильно всегда так: names = append(names, ...). Забыть это присваивание — очень частая ошибка новичков.

Пустой срез создаётся так:

main.go
var todo []string           // пустой, готов к append
nums := []int{}             // то же самое
grid := make([]int, 3)      // три нуля сразу

6.3 range — главный способ пройти по списку

main.go
names := []string{"Аня", "Боря", "Витя"}

for i, name := range names {
    fmt.Printf("%d: %s\n", i, name)
}

// если индекс не нужен:
for _, name := range names {
    fmt.Println(name)
}

// если нужен только индекс:

    fmt.Println(i)
}
0: Аня 1: Боря 2: Витя

6.4 Кусочки среза

main.go
nums := []int{10, 20, 30, 40, 50}

fmt.Println(nums[1:3])   // [20 30]  — с 1-го по 3-й, не включая 3-й
fmt.Println(nums[:2])    // [10 20]  — с начала
fmt.Println(nums[3:])    // [40 50]  — до конца
fmt.Println(nums[:])     // весь целиком

Правило: левая граница включается, правая — нет. Сначала это раздражает, потом привыкаешь: длина куска всегда равна конец − начало.

Срез — это окно, а не копия

Срез не хранит данные сам, он лишь указывает на кусок памяти. Поэтому два среза могут смотреть на одни и те же числа:

a := []int{1, 2, 3}
b := a          // не копия! то же самое место в памяти
b[0] = 99
fmt.Println(a)  // [99 2 3] — изменился и a

Если нужна настоящая копия — делай её явно:

b := make([]int, len(a))
copy(b, a)

Это одна из немногих по-настоящему коварных вещей в Go. Запомни: присваивание среза не копирует данные.

6.5 Полезные операции

main.go
import (
    "fmt"
    "slices"
)

func main() {
    nums := []int{5, 2, 9, 1}

    slices.Sort(nums)                       // сортировка на месте
    fmt.Println(nums)                       // [1 2 5 9]

    fmt.Println(slices.Contains(nums, 9))   // true
    fmt.Println(slices.Index(nums, 5))      // 2
    fmt.Println(slices.Max(nums))           // 9

    slices.Reverse(nums)                    // перевернуть на месте
    fmt.Println(nums)                       // [9 5 2 1]
}

Пакет slices появился в Go 1.21 и очень экономит время. Раньше всё это писали руками.

6.6 Удаление элемента

main.go
names := []string{"Аня", "Боря", "Витя", "Галя"}

names = append(names[:i], names[i+1:]...)
fmt.Println(names)                          // [Аня Витя Галя]

// или проще:

Три точки ... означают «разверни этот срез в отдельные аргументы». Без них Go попытается добавить срез внутрь среза и обидится.

Задача 6.2

Найди в срезе чисел минимум и максимум за один проход, без использования пакета slices.

Решение
main.go
nums := []int{7, -3, 12, 0, 5}

if len(nums) == 0 {
    fmt.Println("пусто")
    return
}

lo, hi := nums[0], nums[0]
for _, n := range nums[1:] {
    if n < lo {
        lo = n
    }
    if n > hi {
        hi = n
    }
}
fmt.Println("мин:", lo, "макс:", hi)

Важная деталь: начальные значения берём из первого элемента, а не из нуля. Иначе на срезе из одних отрицательных чисел максимум окажется нулём.

Из среза чисел собери новый срез только с чётными.

nums := []int{1, 2, 3, 4, 5, 6, 7, 8}

Карты: поиск по имени, а не по номеру

Срез отвечает на вопрос «что под номером 3?». Карта отвечает на вопрос «сколько очков у Ани?».

7.1 Что это

Карта (map, ещё говорят «словарь» или «хеш-таблица») хранит пары «ключ → значение». Ключ может быть строкой, числом — чем угодно сравнимым.

main.go
scores := map[string]int{
    "Аня":  25,
    "Боря": 17,
}

fmt.Println(scores["Аня"])

scores["Витя"] = 30        // добавили
scores["Боря"] = 20        // изменили

fmt.Println(scores)
fmt.Println("всего игроков:", len(scores))
25 map[Аня:25 Боря:20 Витя:30] всего игроков: 3

Тип читается так: map[тип ключа]тип значения. Например map[string][]string — по строке лежит список строк.

7.2 Создание пустой карты

main.go
ages := make(map[string]int)
ages["Аня"] = 14
var map — ловушка

var m map[string]int создаёт карту, равную nil. Читать из неё можно, а записывать — нет: программа упадёт с assignment to entry in nil map. Всегда используй make или литерал map[string]int{}.

7.3 «А есть ли такой ключ?»

Если запросить несуществующий ключ, карта не ругается — она возвращает нулевое значение типа:

main.go
scores := map[string]int{"Аня": 25}

fmt.Println(scores["Петя"])   // 0 — но Пети-то нет!

Как отличить «ноль очков» от «игрока не существует»? Забирать два значения:

main.go
value, ok := scores["Петя"]

if ok {
    fmt.Println("нашли:", value)
} else {
    fmt.Println("такого игрока нет")
}

// короткая форма, когда само значение не нужно:
if _, exists := scores["Аня"]; exists {
    fmt.Println("Аня в игре")
}

Эту конструкцию называют «comma-ok». Она встречается в Go в нескольких местах, запомни её вид.

7.4 Удаление и обход

main.go
delete(scores, "Боря")

for name, score := range scores {
    fmt.Printf("%s: %d\n", name, score)
}
Порядок обхода случайный!

Запусти цикл по карте несколько раз — порядок будет каждый раз разный. Это сделано специально, чтобы никто не писал код, полагающийся на порядок. Если нужен предсказуемый вывод — собери ключи в срез и отсортируй:

keys := make([]string, 0, len(scores))
for k := range scores {
    keys = append(keys, k)
}
slices.Sort(keys)

for _, k := range keys {
    fmt.Println(k, scores[k])
}

7.5 Классика: счётчик

Самое частое применение карт — что-нибудь посчитать.

main.go
text := "мама мыла раму мама мыла окно"
words := strings.Fields(text)      // разбить по пробелам

count := make(map[string]int)
for _, w := range words {
    count[w]++                      // если ключа нет, начнётся с 0
}

fmt.Println(count["мама"])          // 2
fmt.Println(count)
2 map[мама:2 мыла:2 окно:1 раму:1]

Почему это работает без проверок? Потому что count[w] для нового слова даёт 0, а ++ делает 1. Нулевые значения в Go придуманы именно ради таких аккуратных решений.

7.6 Множество (set)

Отдельного типа «множество» в Go нет, но его легко изобразить картой со значением bool или пустой структурой:

main.go
seen := make(map[string]bool)

words := []string{"кот", "пёс", "кот", "ёж", "пёс"}
var unique []string

for _, w := range words {
    if !seen[w] {
        seen[w] = true
        unique = append(unique, w)
    }
}
fmt.Println(unique)   // [кот пёс ёж]

Две группы школьников (два среза имён). Найди тех, кто есть в обеих.

Строки и руны

Почему len("привет") равно 12 и что с этим делать.

8.1 Строка — это байты

Внутри Go строка хранится как последовательность байтов в кодировке UTF-8. Латинская буква занимает один байт, русская — два, эмодзи — четыре.

main.go
fmt.Println(len("hello"))    // 5
fmt.Println(len("привет"))   // 12 !
fmt.Println(len("🐹"))        // 4

Поэтому обращение s[0] даёт байт, а не букву:

main.go
s := "привет"
fmt.Println(s[0])            // 208 — половинка буквы «п»
fmt.Println(string(s[0]))    // мусор

8.2 Руна — это символ

rune — тип, который хранит один символ целиком, каким бы длинным он ни был в байтах. Превратив строку в срез рун, можно работать с буквами нормально:

main.go
s := "привет"
r := []rune(s)

fmt.Println(len(r))          // 6 — настоящее число букв
fmt.Println(string(r[0]))    // п
fmt.Println(string(r[1:4]))  // рив
Правило простое

Английский текст — работай со строкой как есть. Русский, эмодзи, любой юникод — сначала []rune(s), потом что угодно. Или считай длину через utf8.RuneCountInString(s).

8.3 range по строке умный

Приятная новость: цикл range по строке сам разбирает UTF-8 и выдаёт руны.

main.go
for i, ch := range "гоу" {
    fmt.Printf("байт %d: %c\n", i, ch)
}
байт 0: г байт 2: о байт 4: у

Индекс — номер байта, где начинается символ, поэтому он прыгает через два. А сам ch — полноценная руна.

8.4 Пакет strings

main.go
s := "  Привет, Мир!  "

fmt.Println(strings.TrimSpace(s))              // "Привет, Мир!"
fmt.Println(strings.ToUpper(s))                // В ВЕРХНЕМ РЕГИСТРЕ
fmt.Println(strings.ToLower("ГОУ"))            // гоу
fmt.Println(strings.Contains(s, "Мир"))        // true
fmt.Println(strings.HasPrefix("main.go", "m")) // true
fmt.Println(strings.HasSuffix("main.go", ".go"))// true
fmt.Println(strings.Replace(s, "Мир", "Go", 1))// заменить 1 вхождение
fmt.Println(strings.ReplaceAll("а-б-в", "-", "+"))
fmt.Println(strings.Repeat("ха", 3))           // хахаха
fmt.Println(strings.Index("hello", "ll"))      // 2, или -1 если нет

8.5 Разрезать и склеить

main.go
csv := "яблоко,груша,слива"
parts := strings.Split(csv, ",")
fmt.Println(parts)                       // [яблоко груша слива]
fmt.Println(len(parts))                  // 3

back := strings.Join(parts, " и ")
fmt.Println(back)                        // яблоко и груша и слива

// Fields режет по любым пробелам сразу, удобно для текста:
words := strings.Fields("  много   лишних пробелов ")
fmt.Println(len(words))                  // 3

8.6 Строки нельзя менять

main.go
s := "привет"
// s[0] = 'П'      ← ошибка: cannot assign to s[0]

// правильно — через руны:
r := []rune(s)
r[0] = 'П'
s = string(r)
fmt.Println(s)     // Привет

Обрати внимание на кавычки: 'П' в одинарных — это руна (один символ), "П" в двойных — это строка. Разные типы!

Склейка в цикле — медленно

Раз строки неизменяемы, каждое s += "x" создаёт новую строку и копирует старую. В цикле на 100 000 повторений это станет заметно тормозить. Для таких случаев есть strings.Builder:

var b strings.Builder
for i := 0; i < 5; i++ {
    b.WriteString("го ")
}
fmt.Println(b.String())   // го го го го го

Задача 8.3

Шифр Цезаря для латиницы: сдвинь каждую букву на 3 позиции вперёд по алфавиту (a→d, z→c). Напиши функции шифровки и расшифровки.

Решение
main.go
func caesar(s string, shift int) string {
    r := []rune(s)
    for i, ch := range r {
        switch {
        case ch >= 'a' && ch <= 'z':
            r[i] = 'a' + (ch-'a'+rune(shift)+26)%26
        case ch >= 'A' && ch <= 'Z':
            r[i] = 'A' + (ch-'A'+rune(shift)+26)%26
        }
    }
    return string(r)
}

func main() {
    enc := caesar("Hello, World!", 3)
    fmt.Println(enc)              // Khoor, Zruog!
    fmt.Println(caesar(enc, -3))  // Hello, World!
}

Руны — это числа, поэтому ch - 'a' даёт номер буквы в алфавите (0…25). Остаток от 26 заворачивает алфавит в кольцо, а +26 нужно, чтобы отрицательный сдвиг тоже работал.

Проект 2

Крестики-нолики на двоих

Игровое поле, ходы по очереди, проверка победы. Первая программа, где надо подумать над структурой.

Что закрепляем: срезы, вложенные циклы, функции, условия, ввод.

Поле и его печать

main.go
package main

import "fmt"

func printBoard(b []string) {
    fmt.Println()
    for row := 0; row < 3; row++ {
        fmt.Printf("  %s | %s | %s\n", b[row*3], b[row*3+1], b[row*3+2])
        if row < 2 {
            fmt.Println(" ---+---+---")
        }
    }
    fmt.Println()
}

func main() {
    board := []string{"1", "2", "3", "4", "5", "6", "7", "8", "9"}
    printBoard(board)
}
1 | 2 | 3 ---+---+--- 4 | 5 | 6 ---+---+--- 7 | 8 | 9

Поле хранится плоским срезом из 9 клеток, а не «квадратом». Клетка ряда r и столбца c лежит по индексу r*3 + c. Так проще: числа 1–9 на экране прямо соответствуют индексам 0–8.

Проверка победы

main.go
func winner(b []string) string {
    lines := [][3]int{
        {0, 1, 2}, {3, 4, 5}, {6, 7, 8},   // ряды
        {0, 3, 6}, {1, 4, 7}, {2, 5, 8},   // столбцы
        {0, 4, 8}, {2, 4, 6},              // диагонали
    }

    for _, l := range lines {
        if b[l[0]] == b[l[1]] && b[l[1]] == b[l[2]] {
            return b[l[0]]
        }
    }
    return ""
}

Вместо кучи if мы просто перечислили все восемь выигрышных линий и проверяем их циклом. Это типичный приём: описать данные, а не писать логику руками.

Игровой цикл целиком

main.go
func main() {
    board := []string{"1", "2", "3", "4", "5", "6", "7", "8", "9"}
    player := "X"

    for move := 0; move < 9; move++ {
        printBoard(board)

        var cell int
        fmt.Printf("Ход %s, номер клетки: ", player)
        fmt.Scanln(&cell)

        if cell < 1 || cell > 9 {
            fmt.Println("Клетка от 1 до 9!")
            move--
            continue
        }

        i := cell - 1
        if board[i] == "X" || board[i] == "O" {
            fmt.Println("Занято, выбери другую")
            move--
            continue
        }

        board[i] = player

        if w := winner(board); w != "" {
            printBoard(board)
            fmt.Println("Победил", w, "!")
            return
        }

        if player == "X" {
            player = "O"
        } else {
            player = "X"
        }
    }

    printBoard(board)
    fmt.Println("Ничья!")
}

Трюк с move-- перед continue: неудачная попытка не должна считаться ходом, иначе игроки «потратят» её впустую.

Доработай сам

  • Считай счёт по нескольким партиям и спрашивай «сыграем ещё?».
  • Сделай простого компьютерного соперника: ходит в случайную свободную клетку. Потом улучши — пусть сначала проверяет, может ли выиграть одним ходом, и не даёт выиграть противнику.
  • Расширь поле до 4×4 с победой по четыре в ряд. Заметь, как удобно, что победные линии — это просто данные: их можно сгенерировать циклом.

Интерлюдия 2. Программа и внешний мир

stdin, stdout, stderr, аргументы, код возврата и переменные окружения — пять способов, которыми программа общается со всем остальным.

В главе 2 программа спрашивала имя и печатала приветствие. Пора разобраться, куда именно уходит напечатанное и откуда берётся введённое. Это устройство одинаково для Go, Python, C и вообще для всего, что запускается из командной строки, — выучив один раз, будешь понимать любую программу.

И2.1 Три трубы, которые есть у каждой программы

Когда операционная система создаёт процесс, она сразу подключает к нему три канала. У них есть номера — файловые дескрипторы:

№ИмяКуда ведёт по умолчаниюДля чего
0stdinКлавиатураДанные, которые программа читает
1stdoutЭкранРезультат работы
2stderrЭкранСообщения о ходе дела и ошибки

Помнишь write(1, ...) из прошлой интерлюдии? Единица — это и есть stdout. А слово «файловый дескриптор» звучит страшно, но означает всего лишь «номерок, по которому ОС понимает, с каким каналом ты работаешь». Открытый файл, сетевое соединение и клавиатура для программы выглядят одинаково — как поток байтов с номерком.

И2.2 Зачем ошибки отдельно от результата

Оба канала по умолчанию ведут на экран, и разницы вроде бы нет. Она появляется, когда программу используют не человек, а другая программа. Смысл разделения такой:

  • stdout — то, ради чего программу запускали. То, что можно передать дальше по конвейеру или записать в файл.
  • stderr — всё остальное: «начинаю», «файл не найден», «обработано 300 строк». Человеку это нужно, следующей программе — мешает.
main.go
package main

import (
    "fmt"
    "os"
)

func main() {
    fmt.Println("это результат работы")
    fmt.Fprintln(os.Stderr, "а это сообщение о ходе дела")
}

Запусти обычно — увидишь обе строки, они перемешаны. А теперь разложи потоки по файлам:

терминал
go build -o two .

./two > out.txt 2> err.txt   # 1 (stdout) — в один файл, 2 (stderr) — в другой
cat out.txt
cat err.txt
это результат работы а это сообщение о ходе дела

Первая строка пришла из out.txt, вторая — из err.txt. Знак > — это «перенаправь вывод в файл», а цифра перед ним говорит, какой именно канал перенаправлять (без цифры подразумевается 1).

терминал
./two 2>/dev/null    # спрятать болтовню, оставить результат
./two 1>/dev/null    # наоборот: только сообщения
./two > all.txt 2>&1 # оба потока в один файл

/dev/null — специальный «файл-мусорка», всё записанное туда исчезает. В Windows его роль играет nul.

Правило, которое стоит запомнить навсегда

В stdout пишем только то, что является результатом. Всё остальное — в stderr. Тогда твою программу можно будет вставить в конвейер, а не только смотреть на неё глазами.

Проверка простая: если вывод программы направить в файл, должно остаться ровно то, что ты хотел бы там увидеть. Если туда попало «Введите имя:» — правило нарушено.

И2.3 Как это выглядит в Go

Пакет os даёт все три канала как обычные значения: os.Stdin, os.Stdout, os.Stderr. Функции семейства Fprint («F» — от file) отличаются от привычных только тем, что первым аргументом принимают, куда писать:

main.go
fmt.Println("привет")                      // → stdout
fmt.Fprintln(os.Stdout, "привет")          // ровно то же самое
fmt.Fprintln(os.Stderr, "что-то пошло не так")
fmt.Fprintf(os.Stderr, "не нашёл файл %q\n", name)

Есть и готовый инструмент для служебных сообщений — пакет log. Он пишет в stderr по умолчанию и добавляет дату:

main.go
log.Println("это уйдёт в stderr")

log.SetPrefix("myapp: ")
log.SetFlags(0)                 // убрать дату и время
log.Println("а тут без даты и с префиксом")
2026/08/20 19:25:39 это уйдёт в stderr myapp: а тут без даты и с префиксом
err — это не stderr

Два похожих слова, две совершенно разные вещи, и путают их постоянно.

err — переменная-ошибка, которую функция вернула вторым значением — шаблон из главы 5.3. Это данные внутри твоей программы: её можно проверить, передать выше, обработать.

stderr — канал вывода наружу. Связь между ними одна: когда ты решил, что об ошибке нужно сообщить человеку, текст из err печатают именно в stderr.

main.go
data, err := os.ReadFile("config.json")
if err != nil {
    fmt.Fprintln(os.Stderr, "не могу прочитать конфиг:", err)
    os.Exit(1)
}

И2.4 Читаем строку целиком

У Scanln есть неприятная черта: он останавливается на пробеле. Введёшь «Анна Каренина» — получишь только «Анна». Когда нужна вся строка целиком, берут bufio:

main.go
package main

import (
    "bufio"
    "fmt"
    "os"
    "strings"
)

func main() {
    reader := bufio.NewReader(os.Stdin)

    fmt.Print("Введи полное имя: ")
    line, _ := reader.ReadString('\n')
    line = strings.TrimSpace(line)

    fmt.Printf("Записал: %q\n", line)
}
Введи полное имя: Анна Каренина Записал: "Анна Каренина"
  • os.Stdin — «стандартный ввод», то есть клавиатура.
  • ReadString('\n') — читай, пока не встретишь перевод строки.
  • strings.TrimSpace — отрезать пробелы и переводы строк по краям. Без него в конце останется \n.
  • _ (подчёркивание) — «мне не нужно это значение, выброси». ReadString возвращает две вещи: строку и ошибку; ошибку мы здесь игнорируем. Так делать в реальном коде нельзя — в главе 12 разберём, как правильно.
Импорт в скобках

Когда пакетов больше одного, их пишут списком в круглых скобках. Порядок не важен — gofmt сам отсортирует по алфавиту.

И2.5 Читаем stdin: программа-фильтр

До сих пор мы читали ввод у человека. Но stdin — это просто поток байтов, и он с равным успехом может приехать из файла или от другой программы. Такая программа называется фильтром: читает stdin, пишет stdout.

main.go
package main

import (
    "bufio"
    "fmt"
    "os"
    "strings"
)

func main() {
    in := bufio.NewScanner(os.Stdin)
    n := 0

    for in.Scan() {                       // читает по строке, пока есть данные
        n++
        fmt.Printf("%3d | %s\n", n, strings.ToUpper(in.Text()))
    }

    fmt.Fprintf(os.Stderr, "обработано строк: %d\n", n)
}

Теперь одна и та же программа умеет три разных фокуса:

терминал
go build -o filter .

./filter                  # с клавиатуры: печатай строки, закончи Ctrl+D
./filter < text.txt       # взять ввод из файла
cat text.txt | ./filter   # взять ввод у другой программы
1 | ПЕРВАЯ СТРОКА 2 | ВТОРАЯ 3 | ТРЕТЬЯ обработано строк: 3
  • < — «возьми stdin вон из того файла».
  • | (вертикальная черта, пайп) — «соедини stdout левой программы со stdin правой». Между ними ОС держит буфер в памяти, никакого файла на диске не создаётся.
  • Ctrl+D в Linux и macOS (в Windows — Ctrl+Z, потом Enter) означает «данные кончились».
EOF — конец потока

in.Scan() возвращает false, когда читать больше нечего: файл кончился, собеседник закрыл соединение, человек нажал Ctrl+D. Это состояние называется EOF (end of file).

EOF — не ошибка, а нормальное завершение. В Go он даже оформлен отдельным значением io.EOF, и функции вроде ReadString возвращают именно его. Проверять надо так: if err == io.EOF — значит, всё прочитано, можно спокойно заканчивать.

Отсюда растёт вся философия Unix: пусть каждая программа делает одну вещь и умеет читать stdin и писать stdout — тогда из мелких программ можно собирать цепочки любой длины, и никто заранее не должен знать о соседях:

терминал
cat log.txt | ./filter | grep ОШИБКА | head -20

Четыре независимые программы, написанные разными людьми в разные десятилетия, работают как один конвейер. Это ровно то, что делает твоя программа полноценным жителем командной строки.

И2.6 Аргументы командной строки

Второй способ передать программе данные — сказать их прямо при запуске. Всё, что написано после имени программы, попадает в срез os.Args:

main.go
package main

import (
    "fmt"
    "os"
    "strconv"
)

func main() {
    // os.Args[0] — имя самой программы, аргументы начинаются с [1]
    if len(os.Args) < 2 {
        fmt.Fprintln(os.Stderr, "нужно передать число: sq <число>")
        os.Exit(1)
    }

    n, err := strconv.Atoi(os.Args[1])
    if err != nil {
        fmt.Fprintf(os.Stderr, "%q — это не число\n", os.Args[1])
        os.Exit(2)
    }

    fmt.Println(n * n)
}
терминал
./sq 12
./sq
./sq привет
144 нужно передать число: sq <число> "привет" — это не число

Когда аргументов становится много и хочется ключей вида -n 5 или --verbose, руками их разбирать не надо: в стандартной библиотеке есть пакет flag, который сам всё разберёт и напечатает справку.

И2.7 Код возврата: как программа говорит «получилось»

Завершаясь, процесс отдаёт операционной системе одно маленькое число — код возврата (exit code). Договорённость железная:

  • 0 — всё хорошо;
  • любое другое число — что-то пошло не так (какое именно — придумывает автор программы).
терминал
./sq 12
echo $?        # в Windows: echo %ERRORLEVEL%, в PowerShell: $LASTEXITCODE

./sq
echo $?
144 0 1

В Go код возврата задаётся так:

  • main дошла до конца — код 0, ничего писать не нужно;
  • os.Exit(1) — немедленный выход с указанным кодом;
  • log.Fatal("...") — напечатать сообщение в stderr и выйти с кодом 1. Это самый частый способ аварийно закончить маленькую программу;
  • паника без восстановления — код 2.
os.Exit не выполняет defer

os.Exit обрывает процесс мгновенно: отложенные через defer действия не выполнятся, файлы не закроются, буферы не сбросятся. То же касается log.Fatal — внутри него тот же os.Exit(1).

Поэтому в больших программах выход держат в одном месте: main вызывает функцию run() error, а сама только печатает ошибку и выходит с нужным кодом. Тогда все defer внутри отработают нормально.

Зачем это нужно? По коду возврата другие программы понимают, стоит ли продолжать:

терминал
./sq 12 && echo "посчиталось"   # выполнить второе, только если первое вернуло 0
./sq abc || echo "не вышло"     # выполнить второе, только если первое упало

На этом же держатся сборочные скрипты и CI: если go test вернул не 0, сборка считается провалившейся. Именно поэтому нельзя сообщать об ошибке одним лишь текстом — снаружи текст никто не читает, читают число.

Мелочь про go run

Если программа завершилась ненулевым кодом, go run допишет в stderr строчку exit status 1 — это говорит не твоя программа, а сама команда go run. У собранного бинарника такой строки не будет.

И2.8 Переменные окружения

Третий способ настроить программу снаружи — переменные окружения: набор пар «имя = значение», который ОС передаёт процессу при запуске. Обычно так задают то, что меняется от машины к машине: порт, адрес базы данных, ключи доступа.

И2.9 Буферизация, или почему bufio ускоряет в пять раз

Каждый Println — это системный вызов, то есть поход к ядру. Поход дешёвый, но не бесплатный, и на больших объёмах разница становится заметной. Лекарство — буфер: копим данные в памяти и отдаём ядру одним куском.

main.go
// напрямую: 200 000 системных вызовов
for i := 0; i < 200000; i++ {
    fmt.Println(i)
}

// через буфер: несколько сотен вызовов
w := bufio.NewWriter(os.Stdout)
defer w.Flush()                    // без этого хвост данных потеряется!
for i := 0; i < 200000; i++ {
    fmt.Fprintln(w, i)
}
напрямую: 63.5ms через bufio: 13.2ms

Цифры на твоей машине будут свои, но соотношение сохранится. Запомни два факта:

  • в Go os.Stdout не буферизован — написанное появляется сразу, и это удобно для отладки;
  • если завернул вывод в bufio.Writer, обязателен Flush (лучше сразу через defer). Забытый Flush — классическая причина «программа отработала, а файл пустой».
Задача И2.1

Напиши мини-wc: программа читает stdin и печатает количество строк, слов и байт. Результат — в stdout, любые ошибки чтения — в stderr с кодом возврата 1.

Решение
main.go
package main

import (
    "bufio"
    "fmt"
    "os"
    "strings"
)

func main() {
    sc := bufio.NewScanner(os.Stdin)
    lines, words, bytes := 0, 0, 0

    for sc.Scan() {
        line := sc.Text()
        lines++
        words += len(strings.Fields(line))
        bytes += len(line) + 1        // +1 за перевод строки
    }

    if err := sc.Err(); err != nil {
        fmt.Fprintln(os.Stderr, "ошибка чтения:", err)
        os.Exit(1)
    }

    fmt.Printf("строк: %d, слов: %d, байт: %d\n", lines, words, bytes)
}
терминал
printf 'привет мир\nвторая строка тут\n' | ./mywc
строк: 2, слов: 5, байт: 53

Байт больше, чем букв: русские буквы занимают по два байта, как разбирали в главе 8. strings.Fields сам разбивает строку по любым пробелам.

Задача И2.2

Напиши мини-grep: первым аргументом — что искать, ввод — из stdin. Совпавшие строки печатать в stdout, количество совпадений — в stderr. Код возврата: 0 — что-то нашлось, 1 — не нашлось ничего, 2 — забыли аргумент (так делает настоящий grep).

Решение
main.go
package main

import (
    "bufio"
    "fmt"
    "os"
    "strings"
)

func main() {
    if len(os.Args) < 2 {
        fmt.Fprintln(os.Stderr, "как пользоваться: mygrep <что искать>")
        os.Exit(2)
    }
    needle := os.Args[1]

    sc := bufio.NewScanner(os.Stdin)
    found := 0

    for sc.Scan() {
        if strings.Contains(sc.Text(), needle) {
            fmt.Println(sc.Text())
            found++
        }
    }

    fmt.Fprintf(os.Stderr, "совпадений: %d\n", found)
    if found == 0 {
        os.Exit(1)
    }
}
терминал
./mygrep стро < text.txt; echo $?
./mygrep кот < text.txt 2>/dev/null; echo $?
первая строка совпадений: 1 0 1

Теперь программу можно ставить в конвейер: cat log.txt | ./mygrep ошибка | ./mywc — счётчик совпадений в stderr не помешает следующей программе, потому что он не в stdout.

package main

import (
    "bufio"
    "fmt"
    "os"
    "strings"
)

func main() {
    var name string

    if len(os.Args) > 1 {
        name = os.Args[1]
    } else {

    fmt.Println("Привет,", name+"!")
}

Структуры и методы

Свои собственные типы данных: не «имя, возраст, класс» тремя переменными, а один Ученик.

9.1 Проблема

Допустим, нужно хранить книгу: название, автор, год, число страниц. Можно завести четыре среза и следить, чтобы элементы под одним индексом относились к одной книге. Один раз ошибёшься с индексом — и «Война и мир» окажется написана Пушкиным в 1200 году.

Структура склеивает связанные данные в одну штуку.

main.go
package main

import "fmt"

type Book struct {
    Title  string
    Author string
    Year   int
    Pages  int
}

func main() {
    b := Book{
        Title:  "Хоббит",
        Author: "Толкин",
        Year:   1937,
        Pages:  310,
    }

    fmt.Println(b.Title, "—", b.Author)
    fmt.Println(b)
    fmt.Printf("%+v\n", b)      // с именами полей
}
Хоббит — Толкин {Хоббит Толкин 1937 310} {Title:Хоббит Author:Толкин Year:1937 Pages:310}
%+v — лучший друг отладчика

Когда непонятно, что лежит в структуре, печатай её через %+v: увидишь все поля с именами. Это самый быстрый способ понять, что происходит.

9.2 Создание и доступ

main.go
// по порядку полей — коротко, но хрупко

// пустая структура — все поля нулевые
var b2 Book
fmt.Printf("%+v\n", b2)      // {Title: Author: Year:0 Pages:0}

// заполняем позже
b2.Title = "Дюна"
b2.Year = 1965

fmt.Println(b2.Title)

Если добавить в Book новое поле, вариант «по порядку» перестанет компилироваться. Поэтому в реальном коде почти всегда пишут с именами полей.

9.4 Методы: функции, привязанные к типу

Метод — это функция, у которой есть «хозяин». Пишется почти так же, только перед именем добавляется получатель в круглых скобках.

main.go
type Rect struct {
    W, H float64
}

func (r Rect) Area() float64 {
    return r.W * r.H
}

func (r Rect) Perimeter() float64 {
    return 2 * (r.W + r.H)
}

func main() {
    r := Rect{W: 3, H: 4}
    fmt.Println(r.Area())        // 12
    fmt.Println(r.Perimeter())   // 14
}

(r Rect) означает «этот метод работает с прямоугольниками, и внутри он называется r». Дальше вызываешь через точку, как fmt.Println.

9.5 Методы, которые меняют структуру

Вот важный момент. Обычный метод получает копию структуры — изменения пропадут:

main.go
type Counter struct {
    N int
}

func (c Counter) BadInc() {
    c.N++          // меняет копию, оригинал не тронут
}

func (c *Counter) Inc() {
    c.N++          // а вот так меняет настоящий
}

func main() {
    c := Counter{}
    c.BadInc()
    fmt.Println(c.N)   // 0 — ничего не изменилось

    c.Inc()
    c.Inc()
    fmt.Println(c.N)   // 2
}

Звёздочка *Counter означает «указатель на Counter» — то есть метод получает не копию, а адрес оригинала. Про указатели — прямо в следующей главе, а пока запомни правило:

Простое правило выбора

Метод меняет структуру → получатель с звёздочкой: func (c *Counter).
Метод только читает → можно без звёздочки: func (r Rect).
Сомневаешься → ставь звёздочку, хуже не будет. В одном типе лучше не смешивать стили.

9.6 String() — как тип печатает сам себя

Если у типа есть метод String() string, то fmt.Println будет использовать его автоматически:

main.go
type Point struct {
    X, Y int
}

func (p Point) String() string {
    return fmt.Sprintf("(%d, %d)", p.X, p.Y)
}

func main() {
    p := Point{3, 7}
    fmt.Println(p)      // (3, 7), а не {3 7}
}

type Circle struct {
    R float64
}

func (c Circle) Area() float64 {

}

func (c *Circle) Grow(k float64) {

    fmt.Printf("%.2f\n", c.Area())   // 113.10
}

Указатели без страха

Тема, которой все пугают. На самом деле здесь два символа и одна идея.

10.1 Идея

Каждая переменная лежит где-то в памяти, и у этого места есть адрес — как у квартиры. Указатель — это переменная, которая хранит не значение, а адрес другого значения.

Аналогия: у тебя есть листок с домашкой (значение) и записка «домашка лежит в третьем ящике стола» (указатель). По записке можно найти листок и что-то в нём исправить. Отдав другу копию листка, ты не изменишь оригинал. Отдав записку — изменишь.

10.2 Два символа

СимволЧитаетсяЧто делает
&x«адрес x»Берёт адрес переменной
*p«то, что лежит по адресу p»Достаёт значение по адресу
*int«указатель на int»Тип: не число, а адрес числа
main.go
x := 10
p := &x              // p — указатель на x

fmt.Println(x)       // 10
fmt.Println(p)       // 0xc000012345 — адрес, у тебя будет другой
fmt.Println(*p)      // 10 — сходили по адресу

*p = 25              // положили новое значение ПО АДРЕСУ
fmt.Println(x)       // 25 — изменился сам x!

10.3 Зачем это нужно

В Go всё передаётся в функции копией. Значит, обычная функция не может изменить переданную переменную:

main.go
func addOneBad(n int) {
    n++                    // меняем копию
}

func addOne(n *int) {
    *n++                   // меняем оригинал
}

func main() {
    x := 5

    addOneBad(x)
    fmt.Println(x)         // 5

    addOne(&x)
    fmt.Println(x)         // 6
}

Теперь понятно, почему fmt.Scanln(&name) требует амперсанд: функция должна положить прочитанное в твою переменную, а не в свою копию.

10.4 Указатели на структуры

main.go
type Player struct {
    Name string
    HP   int
}

func damage(p *Player, n int) {
    p.HP -= n           // не нужно писать (*p).HP — Go сам разберётся
}

func main() {
    hero := Player{Name: "Аня", HP: 100}

    damage(&hero, 30)
    fmt.Println(hero.HP)   // 70
}
Приятная мелочь

Для полей структуры Go автоматически «разыменовывает» указатель: p.HP работает и для Player, и для *Player. Никаких стрелочек -> как в C.

10.5 Создание сразу по указателю

main.go
hero := &Player{Name: "Аня", HP: 100}   // сразу указатель

hero.HP = 90
fmt.Println(*hero)                       // {Аня 90}

// new() делает то же с нулевыми полями:
p := new(Player)
p.Name = "Боря"

Форма &Struct{...} — самая обычная в реальном Go-коде. Ты будешь видеть её везде.

10.6 nil и паника

main.go
var p *Player       // nil — указатель в никуда

if p == nil {
    fmt.Println("указатель пустой")
}

// fmt.Println(p.Name)   ← panic: nil pointer dereference
Самая частая паника в Go

panic: runtime error: invalid memory address or nil pointer dereference — ты пытаешься обратиться к полю по пустому указателю. Обычно причина в том, что функция вернула nil вместе с ошибкой, а ты ошибку не проверил и пошёл дальше. Всегда проверяй err — тогда таких паник почти не будет.

10.7 Что НЕ нужно оборачивать в указатель

Срезы, карты и каналы уже устроены так, что передаются «по ссылке» — их не нужно передавать через указатель:

main.go
func fill(s []int) {
    s[0] = 99          // изменит оригинал, указатель не нужен
}

func addKey(m map[string]int) {
    m["новый"] = 1     // тоже изменит оригинал
}

Единственное исключение — если внутри функции ты делаешь append и хочешь, чтобы новая длина была видна снаружи. Тогда проще вернуть срез результатом, как это делает сам append.

Задача 10.2

Игра: у героя есть HP. Напиши функции heal и hit, работающие с *Player, и проверь, что HP не уходит ниже нуля и выше 100.

Решение
main.go
type Player struct {
    Name string
    HP   int
}

func hit(p *Player, n int) {
    p.HP -= n
    if p.HP < 0 {
        p.HP = 0
    }
}

func heal(p *Player, n int) {
    p.HP += n
    if p.HP > 100 {
        p.HP = 100
    }
}

func main() {
    hero := &Player{Name: "Аня", HP: 50}

    hit(hero, 80)
    fmt.Println(hero.HP)    // 0

    heal(hero, 200)
    fmt.Println(hero.HP)    // 100
}

Приём «зажать значение в диапазон» называется clamp и встречается постоянно — в играх, в графике, в обработке ввода.

Интерфейсы

Договор «что умеет делать», а не «чем является». Самая элегантная идея в Go.

11.1 Задача

У нас есть круг, прямоугольник и треугольник. У каждого своя формула площади. Хочется написать функцию, которая посчитает суммарную площадь любого набора фигур — не зная заранее, какие именно фигуры в него попадут.

Интерфейс говорит: «мне всё равно, что ты за тип. Если у тебя есть метод Area(), ты мне подходишь».

main.go
package main

import (
    "fmt"
    "math"
)

type Shape interface {
    Area() float64
}

type Rect struct{ W, H float64 }
type Circle struct{ R float64 }

func (r Rect) Area() float64   { return r.W * r.H }
func (c Circle) Area() float64 { return math.Pi * c.R * c.R }

func totalArea(shapes []Shape) float64 {
    sum := 0.0
    for _, s := range shapes {
        sum += s.Area()
    }
    return sum
}

func main() {
    shapes := []Shape{
        Rect{W: 3, H: 4},
        Circle{R: 1},
        Rect{W: 2, H: 2},
    }
    fmt.Printf("%.2f\n", totalArea(shapes))
}

11.2 Никаких «implements»

Обрати внимание: мы нигде не написали «Rect реализует Shape». В Java или C# это обязательно, в Go — нет. Тип подходит под интерфейс автоматически, просто потому что у него есть нужные методы. Это называется неявная реализация.

Утиная типизация

«Если оно ходит как утка и крякает как утка — это утка». Интерфейс описывает поведение, а не родословную. Благодаря этому можно написать интерфейс после типа — например, взять чужую библиотеку и объявить интерфейс, под который её тип случайно подходит. В языках с явной реализацией так нельзя.

11.3 Интерфейсы, которые ты уже видел

ИнтерфейсМетодЗачем
fmt.StringerString() stringКак тип печатается
errorError() stringОшибка. Да, это просто интерфейс!
io.WriterWrite([]byte) (int, error)Куда-то писать: файл, экран, сеть
io.ReaderRead([]byte) (int, error)Откуда-то читать

Мощь io.Writer в том, что одна и та же функция пишет и в файл, и в сетевое соединение, и в буфер в памяти:

main.go
func report(w io.Writer, name string) {
    fmt.Fprintf(w, "Отчёт для %s\n", name)
}

func main() {
    report(os.Stdout, "Ани")          // на экран

    f, _ := os.Create("report.txt")
    defer f.Close()
    report(f, "Бори")                 // в файл

    var buf strings.Builder
    report(&buf, "Вити")              // в строку
    fmt.Println(buf.String())
}

Функция report не знает и не хочет знать, куда именно она пишет. Это и есть хороший дизайн.

11.4 Пустой интерфейс и any

any (раньше писали interface{}) — интерфейс без методов, поэтому под него подходит вообще всё:

main.go
func describe(v any) {
    fmt.Printf("значение %v, тип %T\n", v, v)
}

func main() {
    describe(42)
    describe("текст")
    describe(true)
    describe([]int{1, 2})
}
значение 42, тип int значение текст, тип string значение true, тип bool значение [1 2], тип []int
any — не универсальное решение

Соблазн велик: положил any — и типы больше не мешают. Но так ты теряешь всю помощь компилятора и получаешь ошибки во время работы вместо ошибок при сборке. Используй any только там, где тип действительно заранее неизвестен (разбор JSON, логирование).

11.5 Достать конкретный тип обратно

main.go
func handle(v any) {
    switch x := v.(type) {
    case int:
        fmt.Println("число, удвоенное:", x*2)
    case string:
        fmt.Println("строка длиной", len(x))
    case bool:
        fmt.Println("логическое:", x)
    default:
        fmt.Println("не знаю такого типа")
    }
}

Конструкция v.(type) работает только внутри switch. Есть и одиночная форма с уже знакомым comma-ok:

main.go
if s, ok := v.(string); ok {
    fmt.Println("это строка:", s)
}

11.6 Маленькие интерфейсы лучше больших

В Go принято делать интерфейсы из одного-двух методов. Интерфейс на 15 методов — почти всегда ошибка проектирования: под него мало что подойдёт, и подменить его в тестах будет мучением.

Есть даже поговорка: «чем больше интерфейс, тем слабее абстракция». Стандартная библиотека держит планку — Reader и Writer имеют по одному методу и при этом лежат в основе всего ввода-вывода.

Добавь к примеру 11.1 треугольник и метод Perimeter(). Расширь интерфейс до двух методов и убедись, что все типы его удовлетворяют.

Решение
main.go
type Shape interface {
    Area() float64
    Perimeter() float64
}

type Triangle struct{ A, B, C float64 }

func (t Triangle) Perimeter() float64 { return t.A + t.B + t.C }

func (t Triangle) Area() float64 {
    p := t.Perimeter() / 2
    return math.Sqrt(p * (p - t.A) * (p - t.B) * (p - t.C))
}

Ошибки

В Go ошибки не «выбрасывают» — их возвращают и проверяют. Многословно, зато честно.

12.1 Ошибка — обычное значение

В Python или Java при проблеме бросают исключение, и оно летит вверх, пока кто-нибудь его не поймает. В Go функция просто возвращает ошибку последним значением, и ты решаешь, что с ней делать, прямо здесь.

main.go
n, err := strconv.Atoi("сто")
if err != nil {
    fmt.Println("не получилось:", err)
    return
}
fmt.Println(n)
не получилось: strconv.Atoi: parsing "сто": invalid syntax
Почему так

Критики говорят: «Go заставляет писать if err != nil двадцать раз на файл». Это правда. Взамен ты получаешь важное: глядя на код, сразу видно, где может сломаться и что тогда произойдёт. С исключениями любая строка может внезапно прервать выполнение, и это не написано нигде.

12.2 Создать свою ошибку

main.go
import "errors"

func sqrt(x float64) (float64, error) {
    if x < 0 {
        return 0, errors.New("корень из отрицательного числа")
    }
    return math.Sqrt(x), nil
}

// с подстановкой значений — через Errorf:
func withdraw(balance, n float64) (float64, error) {
    if n > balance {
        return balance, fmt.Errorf("нужно %.2f, а есть только %.2f", n, balance)
    }
    return balance - n, nil
}

Правило хорошего тона: текст ошибки пишется с маленькой буквы и без точки в конце — потому что его часто вкладывают в другую ошибку.

12.3 Заворачивание ошибок

Когда ошибка поднимается по цепочке функций, полезно добавлять контекст — где именно случилась беда. Глагол %w в Errorf «заворачивает» исходную ошибку внутрь новой:

main.go
func loadConfig(path string) error {
    data, err := os.ReadFile(path)
    if err != nil {
        return fmt.Errorf("чтение конфига: %w", err)
    }
    _ = data
    return nil
}

func main() {
    err := loadConfig("нет-такого.txt")
    fmt.Println(err)
}
чтение конфига: open нет-такого.txt: no such file or directory

Получается «след» из сообщений, по которому легко понять, что происходило. При этом внутренняя ошибка не теряется — её можно достать:

main.go
if errors.Is(err, os.ErrNotExist) {
    fmt.Println("файла просто нет — создадим новый")
}

12.4 Что делать с ошибкой

  1. Обработать — попробовать иначе, взять значение по умолчанию, попросить пользователя повторить.
  2. Передать выше — return fmt.Errorf("...: %w", err). Самый частый вариант.
  3. Сообщить и выйти — только в main: log.Fatal(err).
Чего делать нельзя

Игнорировать: value, _ := doSomething(). В учебных примерах это допустимо для краткости, в настоящем коде — источник загадочных багов. Если ошибка действительно не важна, напиши комментарий, почему.

12.5 panic и recover

panic — аварийная остановка программы. Go использует её для по-настоящему безнадёжных ситуаций: выход за границы среза, обращение по пустому указателю, деление на ноль в целых числах.

main.go
nums := []int{1, 2, 3}
fmt.Println(nums[10])   // panic: index out of range [10] with length 3

Есть способ перехватить панику — recover внутри defer:

main.go
func safe() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("поймали панику:", r)
        }
    }()

    var p *int
    fmt.Println(*p)      // паника здесь
}

func main() {
    safe()
    fmt.Println("программа продолжает работать")
}
Не превращай панику в исключения

Соблазн использовать panic/recover как try/catch из других языков очень велик — и это считается плохим стилем в Go. Паника нужна для программистских ошибок («так быть не должно»), а не для ожидаемых проблем вроде «файл не найден» или «пользователь ввёл ерунду». Для них — обычные ошибки.

Задача 12.1

Функция safeDiv(a, b float64) (float64, error). Вызови её с нулём и красиво обработай ошибку.

Решение
main.go
func safeDiv(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("делитель не может быть нулём")
    }
    return a / b, nil
}

func main() {
    for _, pair := range [][2]float64{{10, 2}, {5, 0}} {
        res, err := safeDiv(pair[0], pair[1])
        if err != nil {
            fmt.Printf("%.0f / %.0f → ошибка: %v\n", pair[0], pair[1], err)
            continue
        }
        fmt.Printf("%.0f / %.0f = %.2f\n", pair[0], pair[1], res)
    }
}

Файлы и JSON

Чтобы данные не исчезали при закрытии программы.

14.1 Записать и прочитать файл целиком

Для небольших файлов есть две функции, и больше ничего не нужно:

main.go
package main

import (
    "fmt"
    "os"
)

func main() {
    text := "Привет из файла!\nВторая строка.\n"

    err := os.WriteFile("note.txt", []byte(text), 0644)
    if err != nil {
        fmt.Println("не смог записать:", err)
        return
    }

    data, err := os.ReadFile("note.txt")
    if err != nil {
        fmt.Println("не смог прочитать:", err)
        return
    }

    fmt.Println(string(data))
}
  • []byte(text) — файлы работают с байтами, поэтому строку превращаем в байты, а обратно — через string(data).
  • 0644 — права доступа в стиле Unix: владелец может читать и писать, остальные только читать. На Windows число игнорируется. Пиши 0644 и не думай.

14.2 Читать построчно

Если файл большой (лог на гигабайт), грузить его целиком в память — плохая идея. Читаем по строчке:

main.go
file, err := os.Open("note.txt")
if err != nil {
    fmt.Println(err)
    return
}
defer file.Close()          // закроется при выходе из функции

scanner := bufio.NewScanner(file)
lineNum := 1

for scanner.Scan() {
    fmt.Printf("%d: %s\n", lineNum, scanner.Text())
    lineNum++
}

if err := scanner.Err(); err != nil {
    fmt.Println("ошибка чтения:", err)
}

Вот и пригодился defer из главы 5: файл закроется, даже если посреди цикла случится return.

14.4 JSON: как программы обмениваются данными

JSON — текстовый формат, понятный и человеку, и машине. Так выглядят данные в интернете, в настройках, в API.

data.json
{
  "title": "Хоббит",
  "author": "Толкин",
  "year": 1937

Go превращает структуру в JSON и обратно. Слова в обратных кавычках после поля — теги, они говорят, как поле называется в JSON:

main.go

    Title  string `json:"title"`
    Author string `json:"author"`
    Year   int    `json:"year"`

    if err != nil {
        fmt.Println(err)
        return
    }
    fmt.Println(string(data))

func load() ([]Task, error) {
    data, err := os.ReadFile(fileName)
    if os.IsNotExist(err) {
        return []Task{}, nil       // первого запуска файла ещё нет — это норма
    }
    if err != nil {
        return nil, err
    }

    if err := json.Unmarshal(data, &tasks); err != nil {
        return nil, fmt.Errorf("файл повреждён: %w", err)
    }
    return tasks, nil
}

    if err != nil {
        return err
    }
    return os.WriteFile(fileName, data, 0644)
}

Горутины и каналы

Главная суперсила Go: делать несколько дел одновременно, и делать это просто.

15.1 Проблема ожидания

Программа скачивает десять картинок. Каждая грузится секунду. Последовательно — десять секунд, из которых девять с половиной программа просто ждёт ответа сети, ничего не делая.

Логично запустить все десять загрузок сразу. В большинстве языков это требует потоков, колбэков или async/await с кучей правил. В Go — одного слова.

15.2 go

main.go
package main

import (
    "fmt"
    "time"
)

func work(name string) {
    for i := 1; i <= 3; i++ {
        fmt.Println(name, i)
        time.Sleep(300 * time.Millisecond)
    }
}

func main() {
    go work("первый")     // запускается параллельно
    go work("второй")

    time.Sleep(2 * time.Second)   // ждём, иначе main закончится раньше
    fmt.Println("готово")
}
второй 1 первый 1 первый 2 второй 2 второй 3 первый 3 готово

Слово go перед вызовом означает «запусти это отдельно и не жди». Такая параллельная задача называется горутиной.

Почему горутины дешёвые

Обычный поток операционной системы занимает около мегабайта памяти. Горутина стартует с двух килобайт и растёт по мере надобности, а планировщик Go раскладывает тысячи горутин по нескольким системным потокам сам.

Поэтому запустить сто тысяч горутин — нормально. Запустить сто тысяч потоков — способ уронить компьютер.

main никого не ждёт

Когда заканчивается main, программа завершается вместе со всеми горутинами, даже недоделанными. Убери time.Sleep из примера — не напечатается ничего. Сон здесь — костыль для демонстрации; правильные способы дождаться — ниже.

15.3 Каналы: труба между горутинами

Горутины не должны лезть в общие переменные — это путь к трудноуловимым багам. Вместо этого они передают друг другу значения через каналы.

main.go
func main() {
    ch := make(chan string)      // создаём канал для строк

    go func() {
        time.Sleep(time.Second)
        ch <- "готово!"          // отправляем в канал
    }()

    msg := <-ch                  // ждём здесь, пока что-нибудь придёт
    fmt.Println(msg)
}

Стрелка показывает направление: ch <- x — положить в канал, <-ch — забрать из канала.

Главное свойство: чтение из канала блокирует. Программа стоит на строке <-ch, пока кто-то не отправит значение. Это и есть встроенная синхронизация — никаких блокировок писать не надо.

Девиз Go

«Не общайтесь путём разделения памяти; разделяйте память путём общения». Звучит философски, а на практике означает: не давайте двум горутинам менять одну переменную — пусть одна отправит значение другой по каналу.

15.4 Собираем результаты

main.go
func square(n int, ch chan int) {
    time.Sleep(500 * time.Millisecond)   // как будто долгая работа
    ch <- n * n
}

func main() {
    start := time.Now()
    ch := make(chan int)

    nums := []int{1, 2, 3, 4, 5}
    for _, n := range nums {
        go square(n, ch)
    }

    sum := 0
    for range nums {          // забираем ровно 5 результатов
        sum += <-ch
    }

    fmt.Println("сумма квадратов:", sum)
    fmt.Println("заняло:", time.Since(start))
}
сумма квадратов: 55 заняло: 501ms

Пять задач по полсекунды заняли полсекунды, а не две с половиной. Вот ради чего всё это.

15.5 WaitGroup: дождаться всех

Когда результат не нужен, а нужно просто дождаться окончания — берут sync.WaitGroup. Это счётчик незавершённых задач.

main.go
import "sync"

func main() {
    var wg sync.WaitGroup

    for i := 1; i <= 5; i++ {
        wg.Add(1)                 // +1 к счётчику

        go func() {
            defer wg.Done()       // -1 при выходе, что бы ни случилось
            fmt.Println("задача", i)
            time.Sleep(time.Second)
        }()
    }

    wg.Wait()                     // ждём, пока счётчик не станет нулём
    fmt.Println("все закончили")
}

defer wg.Done() — обязательная привычка. Если горутина выйдет раньше по return и не уменьшит счётчик, Wait зависнет навсегда.

15.6 Закрытие канала и range

main.go
func producer(ch chan int) {
    for i := 1; i <= 5; i++ {
        ch <- i
    }
    close(ch)              // «больше ничего не будет»
}

func main() {
    ch := make(chan int)
    go producer(ch)

    for v := range ch {    // цикл сам закончится при закрытии
        fmt.Println("получил", v)
    }
    fmt.Println("канал закрыт")
}

Закрывает канал всегда отправитель, никогда не получатель. Отправка в закрытый канал — паника.

15.7 Типичные грабли

Deadlock

fatal error: all goroutines are asleep - deadlock! — все горутины чего-то ждут, и никто не может ничего сделать. Обычно причина: пишешь в канал, из которого никто не читает, или читаешь из канала, куда никто не пишет.

func main() {
    ch := make(chan int)
    ch <- 1          // deadlock: некому забрать
    fmt.Println(<-ch)
}

Лечится либо запуском отправки в отдельной горутине, либо буферизованным каналом: make(chan int, 10) позволяет положить 10 значений «в запас» без ожидания.

Гонка данных

Если две горутины меняют одну переменную без синхронизации, результат непредсказуем:

counter := 0
for i := 0; i < 1000; i++ {
    go func() { counter++ }()      // так нельзя!
}

Проверить программу на такие проблемы: go run -race . — встроенный детектор гонок найдёт их и покажет строчки. Обязательно попробуй его на этом примере, зрелище поучительное.

Правильно — либо через канал, либо через sync.Mutex, либо через atomic.Int64.

Запусти три горутины, каждая печатает своё имя пять раз с паузой. Дождись всех через WaitGroup.

Задача 15.2

Посчитай сумму большого среза чисел, разделив работу на 4 горутины, и сравни время с обычным циклом.

Решение
main.go
nums := make([]int, 10_000_000)
for i := range nums {
    nums[i] = i
}

const parts = 4
size := len(nums) / parts
ch := make(chan int, parts)

for p := 0; p < parts; p++ {
    lo := p * size
    hi := lo + size
    if p == parts-1 {
        hi = len(nums)
    }

    go func(chunk []int) {
        sum := 0
        for _, n := range chunk {
            sum += n
        }
        ch <- sum
    }(nums[lo:hi])
}

total := 0
for i := 0; i < parts; i++ {
    total += <-ch
}
fmt.Println(total)

Числа можно записывать с подчёркиваниями для читаемости: 10_000_000. На простом сложении выигрыш будет скромным — тут узкое место в памяти, а не в процессоре. Настоящий эффект горутины дают там, где программа ждёт: сеть, диск, база данных.

Тесты

Как проверять, что код работает — один раз написал, потом проверяется само.

16.1 Зачем

Пока программа маленькая, её можно проверить руками: запустил, потыкал, вроде работает. Когда файлов десять, «потыкать всё» перестаёт помещаться в вечер. И однажды ты меняешь одну функцию, а ломается совсем другая — и узнаёшь об этом от пользователя.

Тест — это код, который проверяет другой код. В Go тесты встроены в язык: не нужно ничего устанавливать.

16.2 Первый тест

Правила простые: файл называется что-то_test.go, функция начинается с Test и принимает *testing.T.

math.go
package main

func Add(a, b int) int {
    return a + b
}
math_test.go
package main

import "testing"

func TestAdd(t *testing.T) {
    got := Add(2, 3)
    want := 5

    if got != want {
        t.Errorf("Add(2, 3) = %d, ожидалось %d", got, want)
    }
}
терминал
go test ./...
ok hello 0.002s

Сломай функцию (напиши a - b) и запусти снова:

--- FAIL: TestAdd (0.00s) math_test.go:10: Add(2, 3) = -1, ожидалось 5 FAIL

Сообщение показывает файл, строку, что получилось и что ожидалось. Пиши сообщения именно в таком виде — сэкономишь себе время.

16.3 Табличные тесты

Проверять хочется много случаев. Копировать функцию десять раз — скучно; в Go принято описывать случаи таблицей:

math_test.go
func TestAdd(t *testing.T) {
    cases := []struct {
        name string
        a, b int
        want int
    }{
        {"обычные", 2, 3, 5},
        {"с нулём", 0, 7, 7},
        {"отрицательные", -2, -3, -5},
        {"разные знаки", -5, 5, 0},
    }

    for _, c := range cases {
        t.Run(c.name, func(t *testing.T) {
            if got := Add(c.a, c.b); got != c.want {
                t.Errorf("Add(%d, %d) = %d, ожидалось %d", c.a, c.b, got, c.want)
            }
        })
    }

Интернет: клиент и сервер

Go придуман для сети. Веб-сервер здесь пишется в десять строк без единой библиотеки.

17.1 Как работает интернет — коротко

Браузер отправляет серверу запрос: «дай мне страницу /about». Сервер отвечает ответом: код состояния (200 — всё хорошо, 404 — не найдено, 500 — сервер сломался) и содержимое. Всё общение — обычный текст по протоколу HTTP.

В Go ты можешь быть и той, и другой стороной.

17.2 Клиент: забрать страницу

main.go
package main

import (
    "fmt"
    "io"
    "net/http"
)

func main() {
    resp, err := http.Get("https://go.dev")
    if err != nil {
        fmt.Println("не достучался:", err)
        return
    }
    defer resp.Body.Close()          // обязательно!

    fmt.Println("статус:", resp.Status)

    body, err := io.ReadAll(resp.Body)
    if err != nil {
        fmt.Println("не прочитал ответ:", err)
        return
    }

    fmt.Println("размер страницы:", len(body), "байт")
}
статус: 200 OK размер страницы: 61239 байт
defer resp.Body.Close()

Без этой строки соединение остаётся висеть. В программе на десять запросов ты ничего не заметишь; в программе на сто тысяч — закончатся файловые дескрипторы, и всё встанет. Пиши defer сразу после проверки ошибки, как рефлекс.

17.3 Забрать данные из API

API — это адрес, который отдаёт не страницу для человека, а JSON для программы. Соединяем главу 14 и эту:

main.go
type Rates struct {
    Base  string             `json:"base"`
    Date  string             `json:"date"`
    Rates map[string]float64 `json:"rates"`
}

func main() {
    url := "https://api.frankfurter.app/latest?from=PLN&to=USD,EUR"

    resp, err := http.Get(url)
    if err != nil {
        fmt.Println(err)
        return
    }
    defer resp.Body.Close()

    if resp.StatusCode != http.StatusOK {
        fmt.Println("сервер ответил:", resp.Status)
        return
    }

    var r Rates
    if err := json.NewDecoder(resp.Body).Decode(&r); err != nil {
        fmt.Println("не разобрал JSON:", err)
        return
    }

    fmt.Println("Курс на", r.Date)
    for code, value := range r.Rates {
        fmt.Printf("1 %s = %.4f %s\n", r.Base, value, code)
    }
}

json.NewDecoder(resp.Body).Decode(&r) — удобнее, чем читать всё в память и потом разбирать: данные разбираются прямо по мере получения.

Проект 4

Проверка сайтов: последовательно и параллельно

Программа берёт список адресов и проверяет, живы ли они. Сначала в лоб, потом — с горутинами. Разница во времени будет наглядной.

Что закрепляем: горутины, каналы, HTTP-клиент, структуры, замер времени.

Версия 1: медленная

package main

    "fmt"
    "net/http"
    "time"
)

func check(url string) string {
    start := time.Now()

    resp, err := http.Get(url)
    if err != nil {
        return fmt.Sprintf("✗ %-28s недоступен", url)
    }
    defer resp.Body.Close()

    return fmt.Sprintf("✓ %-28s %s за %v",
        url, resp.Status, time.Since(start).Round(time.Millisecond))
}

    urls := []string{
        "https://go.dev",
        "https://github.com",
        "https://wikipedia.org",
        "https://pkg.go.dev",
    }

    start := time.Now()
    for _, u := range urls {
        fmt.Println(check(u))
    }
    fmt.Println("\nвсего:", time.Since(start).Round(time.Millisecond))
}

func main() {

        "https://go.dev",
        "https://github.com",
        "https://wikipedia.org",
        "https://pkg.go.dev",

Проект 5 — финальный

Свой веб-сервер с гостевой книгой

Настоящее веб-приложение: HTML-страница, форма, обработка отправки, сохранение в JSON, защита от одновременного доступа. Здесь сходится всё, что было в учебнике.

Что закрепляем: HTTP-сервер, формы, структуры, JSON, мьютексы, шаблоны.

Модель и хранилище

main.go
package main

import (
    "encoding/json"
    "html/template"
    "net/http"
    "os"
    "strings"
    "sync"
    "time"
)

type Entry struct {
    Name string    `json:"name"`
    Text string    `json:"text"`
    At   time.Time `json:"at"`
}

var (
    mu      sync.Mutex     // защита от одновременной записи
    entries []Entry
)

const dataFile = "guestbook.json"

func loadEntries() {
    data, err := os.ReadFile(dataFile)
    if err != nil {
        return                     // нет файла — начинаем с пустого списка
    }
    json.Unmarshal(data, &entries)
}

func saveEntries() {
    data, err := json.MarshalIndent(entries, "", "  ")
    if err != nil {
        return
    }
    os.WriteFile(dataFile, data, 0644)
}
Зачем мьютекс

Сервер обрабатывает каждый запрос в отдельной горутине — Go делает это сам. Значит, два человека могут отправить сообщение одновременно, и обе горутины полезут менять срез entries. Результат непредсказуем: одна запись может потеряться или программа упадёт.

sync.Mutex — это «замок». mu.Lock() означает «пока я здесь, остальные ждут», mu.Unlock() — «проходите». Правило: захватил замок — сразу пиши defer mu.Unlock().

Обработчики и запуск

func showBook(w http.ResponseWriter, r *http.Request) {
    mu.Lock()
    defer mu.Unlock()

    page.Execute(w, entries)
}

func addEntry(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodPost {
        http.Redirect(w, r, "/", http.StatusSeeOther)
        return
    }

    name := strings.TrimSpace(r.FormValue("name"))
    text := strings.TrimSpace(r.FormValue("text"))

    if name == "" || text == "" {
        http.Error(w, "Заполни оба поля", http.StatusBadRequest)
        return
    }
    if len(text) > 1000 {
        text = text[:1000]
    }

    mu.Lock()
    entries = append([]Entry{{Name: name, Text: text, At: time.Now()}}, entries...)
    saveEntries()
    mu.Unlock()

    http.Redirect(w, r, "/", http.StatusSeeOther)
}

func main() {
    loadEntries()

    http.HandleFunc("/", showBook)
    http.HandleFunc("/add", addEntry)

    println("Открой http://localhost:8080")
    http.ListenAndServe(":8080", nil)
}

Последний совет

Код пишется не для компилятора, а для человека, который откроет его через полгода. Скорее всего, этим человеком будешь ты — и ты уже не будешь помнить, что здесь происходило.

Поэтому: понятные имена, короткие функции, проверенные ошибки. Не «умный» код, а понятный. Go специально сделан языком, на котором трудно выпендриваться — пользуйся этим.
